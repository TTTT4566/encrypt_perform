# 古典密码可视化实验室设计规格

## 1. 项目目标

为正在学习密码学的初学者提供一个可直接在浏览器运行的古典密码教学网站。用户从左侧目录选择算法，在右侧阅读简要原理、输入明文与密钥，并通过播放或单步操作观察加密和解密过程。

首版包含以下八个模块：

1. 凯撒密码
2. 仿射密码
3. 维吉尼亚密码
4. Playfair 密码
5. Hill 密码
6. 列置换密码
7. 一次一密
8. 转轮机密码

网站采用原创视觉设计，借鉴 Hello CTF 的文档式信息架构：左侧分层目录、右侧正文和清晰的教学层级，不复制其代码、品牌或视觉资产。

## 2. 成功标准

- 用户进入页面后无需经过宣传页，即可选择算法并开始实验。
- 八个算法都同时支持加密和解密，并提供可直接运行的预置示例。
- 用户可以播放、暂停、前进一步、后退一步、调整速度和重置动画。
- 每一步同时展示当前输入、执行规则、中间状态和输出。
- 对合法示例执行 `解密(加密(明文))` 后能够恢复规范化后的明文。
- 桌面端保持固定左侧目录；移动端目录变成可访问的抽屉。
- 页面在常见桌面与移动尺寸下无横向溢出，正文和控件可在 200% 字体缩放下使用。

## 3. 非目标

- 首版不实现 AES、RSA、RC4、SHA-256 或其他现代密码算法。
- 不提供账户、云端存储、排行榜、练习评分或后端服务。
- 不把教学实现宣传为可用于真实安全通信的密码库。
- 转轮机只实现可解释的三转轮教学模型，不完整复刻历史 Enigma 的全部机械和接线细节。
- 首版 Hill 密码只提供 2x2 密钥矩阵。

## 4. 技术方案

项目使用原生 HTML、CSS 和 JavaScript，作为静态单页应用运行。页面通过 URL 哈希选择模块，例如 `#caesar` 和 `#playfair`。不使用需要构建步骤的前端框架。

建议目录结构：

```text
index.html
assets/
  styles.css
js/
  app.js
  algorithms/
    caesar.js
    affine.js
    vigenere.js
    playfair.js
    hill.js
    columnar.js
    otp.js
    rotor.js
  visualizers/
    renderer.js
    timeline.js
tests/
  algorithms.test.html
```

每个算法模块实现一致的接口：

```js
{
  id,
  normalizeInput(input, options),
  validate(input, key, options),
  encrypt(input, key, options),
  decrypt(input, key, options),
  createSteps(mode, input, key, options)
}
```

`encrypt` 和 `decrypt` 返回最终结果；`createSteps` 返回动画步骤数组。算法计算不直接操作 DOM，界面层只消费步骤数据，因此算法正确性可以独立验证。

## 5. 信息架构

左侧目录分为四组：

```text
古典密码实验室
├─ 开始学习
├─ 替代密码
│  ├─ 凯撒密码
│  ├─ 仿射密码
│  ├─ 维吉尼亚密码
│  └─ Playfair 密码
├─ 数学与置换
│  ├─ Hill 密码
│  └─ 列置换密码
└─ 密钥流与机械密码
   ├─ 一次一密
   └─ 转轮机密码
```

桌面端目录固定在左侧，可滚动并高亮当前算法。内容区在顶部显示面包屑、算法名称、难度和所属类型。移动端使用顶部菜单按钮打开目录抽屉，关闭后焦点回到菜单按钮。

## 6. 视觉方向

视觉主题为“网络安全教程与密码实验台”：

- 深蓝灰侧边栏配合青蓝色当前项标记。
- 正文使用高对比度浅色背景，避免大面积装饰和宣传式首屏。
- 正文使用适合中文阅读的无衬线字体；字符、公式、矩阵和位串使用等宽字体。
- 算法流程使用卡片、表格、字母格、矩阵格和连接线表达，不使用与教学无关的图片。
- 动画颜色含义保持一致：蓝色表示当前输入，黄色表示正在处理，绿色表示已完成，红色只表示错误。
- 所有颜色状态同时配有文字或图形标识，不能只靠颜色传达含义。

## 7. 通用算法页面

每个模块共用以下结构：

1. 简短原理和核心公式。
2. 加密／解密模式切换。
3. 明文或密文输入区。
4. 算法专用密钥和选项。
5. 预置示例、开始、播放／暂停、上一步、下一步、重置和速度控制。
6. 主动画舞台。
7. 当前步骤解释、公式代入和中间状态。
8. 最终结果及复制按钮。
9. 安全性、已知弱点和教学用途提醒。

动画时间线是有限状态机：`idle`、`ready`、`playing`、`paused`、`complete`、`error`。切换算法或修改输入会停止当前播放并回到 `ready`，防止旧动画继续修改新页面。

## 8. 八个模块的具体行为

### 8.1 凯撒密码

- 密钥是 0 到 25 的整数位移量。
- 动画显示双层字母环、当前明文字母、移动方向和结果字母。
- 解密使用反向位移。

### 8.2 仿射密码

- 密钥为整数 `a` 和 `b`，要求 `gcd(a, 26) = 1`。
- 每个字符展示编号、`(a*x+b) mod 26` 的代入和结果。
- 解密展示 `a` 的模逆元以及逆变换。

### 8.3 维吉尼亚密码

- 密钥只接受英文字母，并按有效输入字符重复。
- 动画同步高亮明文字母、密钥字母、Vigenere 方阵交点和结果。
- 保留标点时，标点不消耗密钥字符。

### 8.4 Playfair 密码

- 使用 5x5 字母方阵，默认合并 I/J。
- 展示密钥去重、补齐字母表和明文二元组预处理。
- 动画区分同行、同列、矩形三种规则，并展示填充字母 X。
- 解密保留算法产生的填充字符，由用户根据上下文判断是否移除。

### 8.5 Hill 密码

- 使用 2x2 整数矩阵作为密钥。
- 验证矩阵行列式在模 26 下存在逆元。
- 动画展示字母向量、矩阵乘法、模 26 和结果向量。
- 奇数长度输入在末尾补 X；解密结果明确标出可能的补位字符。

### 8.6 列置换密码

- 密钥使用不重复数字排列或可确定唯一排序的关键词。
- 动画先逐行填充网格，再按密钥列顺序高亮读取。
- 解密先计算各列长度，再回填网格并按行读取。

### 8.7 一次一密

- 教学模式将 A-Z 映射为 0-25，并演示模 26 加减；同时提供位串 XOR 视图解释 Vernam 思想。
- 密钥长度必须不短于规范化后的消息长度。
- 页面明确解释真正的一次一密要求密钥随机、等长、保密且永不复用。

### 8.8 转轮机密码

- 使用三个可配置初始位置的教学转轮和固定反射路径。
- 每次处理字符前推动快转轮，并在进位条件满足时推动下一转轮。
- 动画展示字符通过三个转轮、反射后返回的完整路径。
- 使用相同转轮配置和初始位置再次处理密文可恢复明文。

## 9. 输入规范和错误处理

- 默认将英文字母转换为大写。
- 用户可以选择保留或忽略空格、数字和标点；非字母不参与密码运算。
- 输入为空、密钥非法、矩阵不可逆、密钥长度不足等情况在输入附近显示明确错误。
- 有验证错误时不能开始播放，界面保留用户输入。
- 复制结果失败时给出非阻塞提示，不丢失结果。
- URL 中出现未知算法标识时回到“开始学习”，不显示空白页面。

## 10. 可访问性和响应式行为

- 主体文字不小于 16px，常用控件标签不小于 14px。
- 所有表单控件都有可见标签；按钮可通过键盘操作。
- 播放状态、错误和最终结果通过可读文本更新，不依赖动画本身。
- 尊重 `prefers-reduced-motion`，在减少动态效果时改用即时状态切换。
- 桌面端内容宽度控制在适合阅读和实验的范围；复杂矩阵或网格在窄屏中可局部横向滚动，但页面本身不产生横向滚动。

## 11. 验证策略

每个算法至少包含：

- 一个书中或标准教材的已知加密示例。
- 对应解密示例。
- 一组往返测试：`decrypt(encrypt(normalized)) === normalized`。
- 密钥边界和非法输入测试。
- 动画最后一步结果与直接计算结果一致的测试。

页面级检查包括：

- 八个目录链接和 URL 哈希切换。
- 播放、暂停、前后步、速度和重置。
- 切换模块时旧时间线被销毁。
- 桌面和移动布局、键盘导航及减少动态效果模式。
- 浏览器控制台无运行时错误。

## 12. 首版交付范围

首版交付一个本地可运行的完整静态网站，包括八个算法、统一动画框架、响应式目录、预置示例、输入验证和教学说明。首版完成后由用户进行使用测试；后续修改以实际使用反馈为依据，不在本阶段预先加入现代密码模块或额外平台功能。
