# 现代密码算法教学扩展设计规格

## 1. 目标

在现有古典密码可视化实验室中新增五个现代算法教学模块：AES-128、RSA、RC4、SHA-256 和 MD5。网站继续使用原生 HTML、CSS 与 JavaScript，在浏览器本地完成所有计算，不引入后端服务或第三方运行时依赖。

扩展后的站点包含 13 个实验。用户可以沿用现有左侧目录、实验参数区和动画时间线，逐步观察字节、状态矩阵、密钥、寄存器与轮函数的变化。

## 2. 教学边界

- 所有新增实现都用于解释算法，不作为生产密码库。
- AES 使用 AES-128-ECB 和 PKCS#7 填充。ECB 便于展示核心轮函数，但页面必须说明它会泄露数据模式。
- RSA 使用可编辑的小素数参数，便于展示密钥推导和模幂运算，不具备真实安全强度。
- RC4 和 MD5 页面必须明确标注算法已不安全。
- SHA-256 和 MD5 是单向摘要算法，只提供“生成摘要”，不显示“解密”。
- 输入长度限制为 256 个 UTF-8 字节，避免教学动画产生不可控数量的步骤。

## 3. 信息架构

左侧目录保留已有古典密码分组，并新增：

```text
现代密码
├─ 分组密码
│  └─ AES-128
├─ 公钥密码
│  └─ RSA
├─ 流密码
│  └─ RC4
└─ 摘要算法
   ├─ SHA-256
   └─ MD5
```

首页实验数由 8 更新为 13，并将学习路径扩展为“古典变换 → 对称密码 → 公钥密码 → 消息摘要”。现代模块延续现有白色文档式界面，不创建独立站点或第二套导航。

## 4. 源码与构建结构

`classical-cipher-lab` 是唯一手工维护的站点源码。`dist` 是托管输出，由构建脚本从源码生成，不再手工修改。旧 `site` 目录是过时副本，将在迁移完成后删除，避免再次编辑错误副本。

新增结构：


## 5. 能力驱动的算法接口

现有算法接口扩展为能力驱动结构：

```js
meta: {
  id,
  title,
  code,
  category,
  family,
  modes: ['encrypt', 'decrypt'] | ['hash'],
  inputEncoding: 'text' | 'hex' | 'numbers',
  outputEncoding: 'text' | 'hex' | 'numbers',
  showPreserveOption: boolean,
  keyFields,
  defaults,
  summary,
  formula,
  note
}
```

算法函数仍返回统一结果：

```js
{
  output,
  normalized,
  steps,
  details
}
```

古典算法默认拥有 `encrypt` 和 `decrypt` 两种模式。SHA-256 与 MD5 只暴露 `hash`。应用层根据 `meta.modes` 生成按钮、输入标签和结果标签，而不是针对算法 ID 写死分支。

## 6. 字节与编码规范

- 文本输入统一通过 `TextEncoder` 转为 UTF-8 字节。
- AES、RC4 的加密输出使用大写十六进制；解密输入接受忽略空格的十六进制。
- RSA 密文使用空格分隔的十进制整数；每个整数代表一个加密后的 UTF-8 字节。
- SHA-256 和 MD5 输出使用小写十六进制摘要。
- 解密得到的字节必须通过严格 UTF-8 解码；非法序列显示明确错误，不静默替换。
- 十六进制输入必须为偶数长度且仅包含 `0-9A-Fa-f`。

## 7. AES-128 模块

### 7.1 参数与结果

- 模式：AES-128-ECB。
- 密钥：恰好 16 个 UTF-8 字节。
- 填充：PKCS#7，始终添加填充块；完整块输入会追加 16 字节填充。
- 加密结果：大写十六进制。
- 解密输入：十六进制；长度必须是 16 字节的整数倍。

### 7.2 动画

每个分组依次展示：

1. UTF-8 编码与 PKCS#7 填充。
2. 4×4 状态矩阵装载。
3. 初始 `AddRoundKey`。
4. 第 1 至 9 轮的 `SubBytes`、`ShiftRows`、`MixColumns`、`AddRoundKey`。
5. 第 10 轮的 `SubBytes`、`ShiftRows`、`AddRoundKey`。
6. 输出矩阵与十六进制密文。

解密按逆变换顺序展示。密钥扩展视图显示 11 个轮密钥，当前轮密钥随时间线高亮。

## 8. RSA 模块

### 8.1 参数与结果

- 默认参数：`p = 61`、`q = 53`、`e = 17`。
- 验证 p、q 为不同素数，且 `gcd(e, φ(n)) = 1`。
- 自动计算 `n = pq`、`φ(n)` 与私钥指数 `d`。
- 每个 UTF-8 字节作为一个消息整数，要求 `n > 255`。
- 加密输出为空格分隔的十进制整数。
- 解密将整数恢复为 UTF-8 字节和文本。

### 8.2 动画

1. 验证 p 与 q。
2. 计算 n 和 `φ(n)`。
3. 使用扩展欧几里得算法计算 d。
4. 展示文本到 UTF-8 字节的映射。
5. 对每个字节展示平方-乘模幂过程。
6. 拼接密文分组或恢复文本。

## 9. RC4 模块

### 9.1 参数与结果

- 密钥为 1 至 256 个 UTF-8 字节。
- 加密输入为 UTF-8 文本，输出为大写十六进制。
- 解密输入为十六进制，输出为严格 UTF-8 文本。
- 加解密共享同一 XOR 密钥流过程。

### 9.2 动画

1. 初始化 `S[0..255]`。
2. 完整展示 KSA 的 256 次 j 更新与交换。
3. 对每个消息字节展示 PRGA 的 i、j、交换、t 与密钥流字节。
4. 展示消息字节、密钥流字节和 XOR 结果。

动画使用分页的置换表视图，只突出当前索引，避免一次显示 256 个大方格。

## 10. SHA-256 模块

- 输入为 UTF-8 文本，输出 256 位小写十六进制摘要。
- 只提供“生成摘要”模式。
- 动画展示原始字节、追加 `0x80`、零填充和 64 位长度字段。
- 每个 512 位分组展示 `W[0..63]` 消息调度。
- 64 轮逐轮展示 a 至 h、`Σ0`、`Σ1`、`Ch`、`Maj`、`T1` 和 `T2`。
- 每个分组结束后展示与当前哈希状态的模 `2^32` 累加。

## 11. MD5 模块

- 输入为 UTF-8 文本，输出 128 位小写十六进制摘要。
- 只提供“生成摘要”模式。
- 动画展示小端长度填充、16 个消息字和四轮共 64 步压缩。
- 每一步展示当前函数 F/G/H/I、消息索引、常量、循环左移和寄存器状态。
- 最终以小端顺序拼接 A、B、C、D。

## 12. 可视化组件

在现有渲染器中增加以下步骤类型：

- `byte-grid`：字节序列、填充和 XOR。
- `state-matrix`：AES 4×4 状态矩阵和轮密钥。
- `key-schedule`：AES 轮密钥生成。
- `modular-math`：RSA 素数、欧几里得与模幂过程。
- `permutation`：RC4 S 盒窗口与交换位置。
- `registers`：SHA-256 和 MD5 工作寄存器。
- `message-schedule`：哈希消息调度窗口。

颜色语义沿用现有主题：当前输入、正在处理、已完成和错误分别使用一致的视觉状态。所有状态同时提供文本标签，不只依赖颜色。

## 13. 表单与交互

- 加密模块显示“加密／解密”；摘要模块显示单个“生成摘要”状态。
- 页面根据模式自动切换“明文／密文／消息”和结果标签。
- 不适用于现代算法的“保留标点”选项由元数据隐藏。
- 载入示例必须同时恢复消息、密钥、模式和算法专用参数。
- 切换模式、算法或重新运行时停止旧时间线。
- 大量步骤仍支持播放、暂停、前后步、速度调整和重置。
- 输出复制行为保持不变。

## 14. 错误处理

需要覆盖：

- AES 密钥不是 16 个 UTF-8 字节。
- AES 或 RC4 密文不是合法十六进制。
- AES 密文长度不是 16 字节整数倍或 PKCS#7 填充损坏。
- RSA 参数不是整数、不是素数、p 与 q 相同、e 不互素或 n 不足以容纳字节。
- RSA 密文包含非法数字或超出 `[0, n)`。
- RC4 密钥为空或超过 256 字节。
- 输入超过 256 个 UTF-8 字节。
- 解密字节不是合法 UTF-8。

验证失败时不创建动画步骤，并在参数区显示中文错误。

## 15. 安全提示

- AES 页面说明 ECB 只用于观察 AES 核心轮函数，真实系统应使用带认证的模式，如 AES-GCM。
- RSA 页面说明小素数和逐字节裸 RSA 极不安全，真实系统必须使用足够大的密钥和 OAEP 等填充。
- RC4 页面说明其密钥流存在偏差，已被现代协议淘汰。
- SHA-256 页面说明摘要不等于加密，也不应用裸摘要保存密码。
- MD5 页面说明碰撞攻击已实用化，不适合安全校验、签名和密码存储。

## 16. 验证策略

### 16.1 已知向量

- AES-128：FIPS-197 单分组向量，密钥 `000102...0F`、明文 `001122...FF`、密文 `69C4E0D86A7B0430D8CDB78070B4C55A`。
- RSA：`p=61`、`q=53`、`e=17`，验证 `65^17 mod 3233 = 2790` 且可恢复 65。
- RC4：密钥 `Key`、明文 `Plaintext`，密文 `BBF316E8D940AF0AD3`。
- SHA-256：`abc` 对应 `ba7816bf...15ad`。
- MD5：`abc` 对应 `900150983cd24fb0d6963f7d28e17f72`。

### 16.2 行为测试

- AES、RSA 和 RC4 对 UTF-8 示例执行加解密往返。
- SHA-256 与 MD5 对空字符串、`abc` 和多分组输入验证摘要。
- 每个算法验证非法参数和输入边界。
- 每个模块至少生成一个动画步骤，最后一步结果与直接计算一致。
- 目录、首页计数和路由准确包含 13 个模块。
- 摘要模块不渲染解密按钮。
- 构建后 `dist` 与源码入口一致，并能由启动脚本提供服务。

## 17. 完成标准

- 五个现代算法模块均可通过目录进入并运行预置示例。
- AES、RSA、RC4 可加密、解密并逐步播放。
- SHA-256、MD5 可生成标准摘要并逐步播放。
- 所有新旧算法测试和页面验收测试通过。
- `npm run build` 可从唯一源码重建 `dist`。
- 旧 `site` 副本已删除，不再存在多份可误改源码。
- README、页面标题、实验计数和安全提示已更新。
